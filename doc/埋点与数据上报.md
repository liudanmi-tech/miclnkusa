## 二、初始化流程

### 启动顺序（`WorkSurvivalGuideApp.init()`）

```
App 启动
  ├── 1. TikTok Business SDK 初始化
  ├── 2. Kochava SDK 初始化（配置 ATT 等待时间）
  └── 3. SplashCoordinator 展示开屏页
           └── scenePhase = .active 时触发 ATT 弹窗（仅一次）
                    └── Kochava 等待 ATT 结果后读取 IDFA
```

## 三、ATT 弹窗

- **触发时机**：`SplashCoordinator.onChange(scenePhase)` 检测到 `.active` 时
- **触发条件**：仅首次（`attRequested` flag 保证只触发一次）
- **弹窗文案**（`Info.plist`）：
  `"We use this to measure ad performance and improve your experience."`
- **Kochava 与 ATT 的协作**：Kochava 不自己弹窗，等待 60 秒后读取 ATT 状态。若用户已授权，Kochava 带 IDFA 上报，走正常归因端点。

## 四、自动上报的事件（SDK 内置，无需手动埋点）

| 事件 | SDK | 触发时机 |
|------|-----|---------|
| `AppInstall` | TikTok Business SDK | 首次安装后第一次启动 |
| `AppLaunch` | TikTok Business SDK | 每次启动 |
| `install` | Kochava | 首次安装后第一次启动 |
| `launch` | Kochava | 每次启动 |

## 五、手动埋点事件

### 5.1 登录 / 注册（`AuthViewModel.swift`）

| 事件名 | SDK | 触发场景 |
|--------|-----|---------|
| `"Login"` | TikTok | 邮箱登录成功 |
| `"Login"` | TikTok | Apple Sign In 成功 |
| `"Registration"` | TikTok | 邮箱注册成功 |
| `identify(externalID)` | TikTok | 登录成功后关联内部用户 ID |
| `IdentityLink.register("User ID", userInfo.user_id)` | Kochava | 登录成功后关联用户 ID |

> 注：`identify` 和 `IdentityLink` 只传内部 `user_id`，不传邮箱等 PII 给 Kochava。TikTok `identify` 传了 `email`（TikTok 协议允许）。

### 5.2 订阅（`SubscriptionManager.swift`）

| 事件名 | SDK | 触发场景 |
|--------|-----|---------|
| `"Subscribe"` | TikTok | `Transaction.updates` 监听到有效订阅交易时 |

## 八、数据流向

```
用户行为
  │
  ├── TikTok Business SDK ──→ TikTok 服务器
  │         └── 自动上报 AppInstall/AppLaunch
  │         └── 手动上报 Login / Registration / Subscribe
  │         └── 用于：TikTok 广告转化归因 + 事件优化
  │
  └── Kochava SDK ──→ Kochava 服务器
            └── 自动上报 install / launch
            └── IdentityLink 关联用户 ID
            └── 用于：跨渠道归因汇总报表（当前主要用于 TikTok 辅助）
```
