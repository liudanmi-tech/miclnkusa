## 三、整体执行流水线（9步）

```
Step 1  更新 image_status = "generating"（DB）
Step 2  场景类型检测（场景1 vs 场景2）
Step 3  构建对话文本（场景1带[我]/[对方]标签，场景2纯口述）
Step 3.5 [场景2] 预加载用户的非自己档案列表（纯DB，无AI）
Step 4  Gemini Flash 提取场景描述（场景1单独调，场景2合并调）
Step 5  加载档案照片（按场景类型分路）
Step 6  并行生成所有图片（调 generate_image_from_prompt）
Step 7  组装 scene_images JSON
Step 8  写入 strategy_analysis.scene_images（或暂存+重试）
Step 9  更新 image_status = "completed"（DB）
```

## 四、Step 2：场景类型检测

**判断逻辑：**

```python
speakers = 对话中所有不重复的 speaker 标签
speaker_count = len(speakers)

if speaker_count == 1 AND speaker_mapping 有值:
    mapped_pid = speaker_mapping[single_speaker]
    p = DB.get(Profile, mapped_pid)
    if p.relationship_type in ("自己", "Self", "self"):
        is_narration_mode = True   # → 场景2（事后自述）
    else:
        is_narration_mode = False  # → 场景1（单人但非用户）
else:
    is_narration_mode = False      # → 场景1（多人对话）
```

| 情况 | 判断结果 |
|------|---------|
| 2个说话人（如 Speaker_0 + Speaker_1） | 场景1 |
| 1个说话人，声纹匹配为"自己" | 场景2 |
| 1个说话人，声纹匹配为"领导"等他人 | 场景1 |
| speaker_mapping 为空 / None | 场景1 |
| Chat Session（全部 is_me=True） | 场景2（Speaker_0 → Self 档案） |

## 五、Step 4：场景提取（Gemini Flash）

### 场景1（多人/非自我）：单独一次调用

**输入：** 带 `[我]`/`[对方]` 角色标签的对话文本

**Prompt 要求：**
- 提取 1-3 个最有画面感的场景
- 必须用英文输出
- 必须说明谁在做什么（用"I"代指用户，"the other person"代指对方）
- 不能颠倒角色动作主体

**返回结构：**
```json
{"scene_count": 2, "scenes": ["I am reporting to the other person", "..."]}
```

---

### 场景2（事后自述）：合并一次调用（场景提取 + 人名匹配）

**输入：** 纯口述文本 + 用户档案列表（仅非 Self 档案名）

**Prompt 要求：**
- 识别 1-3 个场景（英文）
- 同时做人名匹配：口述中的人名 → 档案名（考虑谐音/昵称，如"妞蛋"→"liudan"）
- 高置信度才匹配，不确定填 null

**返回结构：**
```json
{
  "name_mapping": {"张经理": "张三", "妞蛋": "liudan", "老板": null},
  "scenes": ["I am talking to Zhang San about the project", "..."]
}
```

匹配结果写入 `_name_mapping` 和 `_matched_profiles`，同时异步写回 `kg_persons.profile_id`（用于知识图谱记忆关联）。

## 六、Step 5：档案照片加载（两条路径）

### 场景1 路径：`_get_profile_reference_images()`

**查找顺序（三级兜底）：**

```
Step 1: 从 analysis_result.speaker_mapping 里找声纹匹配的档案
        → 分出 left_pid（relationship="自己"）和 right_pid（其他人）

Step 2: left_pid 仍为空
        → 直接查用户的"自己"档案（有 photo_url 的优先）

Step 3: right_pid 仍为空
        → 查本次会话关联的非自己档案
          （Profile.audio_session_id == session_id 且 photo_url 非空）

最终：加载 left + right 的 OSS 照片，返回 [(bytes, mime), ...]
```

> 注意：此函数从旧的 `analysis_result.speaker_mapping`（声纹匹配写入）取数据，与传入参数 `speaker_mapping` 无关。

---

### 场景2 路径：`_fetch_profile_image_from_oss()`

**两类照片分别加载：**

**① 他人照片**（口述中提到的人，来自 Step4 名字匹配结果）：

```
遍历 _matched_profiles:
  有档案 + 有照片 → 从 OSS 取图 → people_refs[人名] = {"photo": ..., "is_pet": bool}
  有档案 + 无照片 → 调 _infer_person_appearance（Gemini 推断外貌文字）
                    → people_refs[人名] = {"appearance": "穿西装的中年男性"}
```

**② 用户自己的照片**：

```python
if speakers and speaker_mapping and fetch_profile_image_fn:  # ← Chat Session bug 在此
    self_pid = speaker_mapping[speakers[0]]
    _self_prof = DB.get(Profile, self_pid)
    user_photo = fetch_profile_image_fn(user_id, self_pid, _self_prof.photo_url)
```

---

### `_fetch_profile_image_from_oss` 内部逻辑

```
1. 从 photo_url 提取 OSS session_id（正则匹配 "profile_<uuid>"）
   例：photo_url = "https://cdn.../images/uid/profile_f264cb3d-xxx/0.png"
        → oss_session_id = "profile_f264cb3d-xxx"

2. 若无法提取 → 回退路径 "profile_{profile_id}"

3. 构建 OSS key：images/{user_id}/{oss_session_id}/0.png

4. 从 R2 拉取 → 检测 MIME（JPEG/PNG）

5. 若超过 7MB → 跳过，返回 None

6. _compress_profile_image()：压缩到 300KB 以内（加快 Gemini 处理）

7. 返回 (bytes, mime_type) 或 None
```

## 七、Step 6 生图：各情况下的入参汇总

进入 `gen_one(i, scene)` 时，按场景类型和人数组装不同的 `ref_images`、`ref_labels`、`scene_with_profile`。

### 场景2（Chat Session / 事后自述）

| 情况 | user_photo | people_refs | ref_images 内容 | ref_labels |
|------|-----------|-------------|-----------------|------------|
| 只有用户，无他人 | 有 | 空 | `[user_photo]` | `[{"name":"用户","is_pet":false}]` |
| 只有用户，无他人 | 无（当前 bug） | 空 | `[]` → `None` | `None` |
| 用户 + 1个有照片的人 | 有 | `{张三: {photo: ...}}` | `[user_photo, 张三_photo]` | `[用户, 张三]` |
| 用户 + 1个无照片的人 | 有 | `{张三: {appearance: "穿西装..."}}`  | `[user_photo]` | `[用户]` |
| 用户 + 宠物（有照片） | 有 | `{小黑: {photo:..., is_pet:true}}` | `[user_photo, 小黑_photo]` | `[{用户,pet=F}, {小黑,pet=T}]` |

无照片的他人 → 外貌描述文字注入到 `scene_with_profile` 最前：
```
"对方为穿正式西装的中年男性领导。I am reporting to the other person..."
```

### 场景1（多人录音）

| 情况 | get_profile_refs_fn 结果 | ref 内容 | 降级策略 |
|------|--------------------------|----------|---------|
| 声纹匹配到2人且都有照片 | `[(left_bytes,mime),(right_bytes,mime)]` | 2张参考图 | — |
| 仅匹配到1人（如只有用户） | `[(left_bytes,mime)]` | 1张参考图 | — |
| 完全没有照片 | `[]` | `None` | 调 `_analyze_character_profiles` 推断文字外貌 → 注入 prompt |

## 八、`generate_image_from_prompt` 内部：按参考图数量分支

### 无参考图（`n_refs = 0`）

```
prompt = style_prefix
       + 【重要】画面中左侧人物固定为用户，右侧人物固定为对方，不能颠倒角色
       + scene_description
       + 4:5 竖版尺寸要求
       + 禁止水印

contents_list = [style_ref_jpg, prompt_text]
```

Gemini 完全基于文字描述生成通用角色，无人物外貌参考。

---

### 1-2张参考图（`n_refs = 1` 或 `2`）

```
prompt = style_prefix
       + 【重要】画面中左侧人物固定为用户，右侧人物固定为对方（位置规则）
       + 【人物一致性要求】以下参考照片是真实形象，绘制时必须严格还原：
           - 第1张参考图：{name}的真实照片，必须完整还原外貌特征、体型、整体形象
           - 第2张参考图：{name}（若有宠物：必须保持动物原形，严禁拟人化）
       + scene_description
       + 【再次强调】所有人物外貌必须与参考照片高度一致（最高优先级）
       + 4:5 竖版尺寸要求 + 禁止水印

contents_list = [style_ref_jpg, photo_1_bytes, photo_2_bytes（若有）, prompt_text]
```

---

### 3张及以上参考图（`n_refs >= 3`，多人场景含宠物）

```
prompt = style_prefix
       + 【重要】画面中必须出现 N 个不同角色，每个角色有独立外形和动作，不固定左右位置
       + 【角色一致性要求】以下 N 张参考照片分别对应 N 个角色：
           - 第1张：用户——照片中是什么形象就画什么
           - 第2张：张三——场景中凡提及张三的均以此照片为外貌参考
           - 第3张：小黑【宠物/动物角色】——必须保持动物原形，严禁拟人化，严禁变为人形
       + scene_description
       + 【再次强调】N 个独立角色一个都不能少，外貌与参考照片高度一致
       + 【动物角色最高优先级】小黑必须是真实动物形态（优先于一切风格要求）
       + 4:5 竖版尺寸要求 + 禁止水印

contents_list = [style_ref_jpg, photo_1, photo_2, photo_3, ..., prompt_text]
```

## 九、风格参考图机制

每次生图前，自动加载本地风格参考图：

```
/opt/gemini-audio-service/style_references/{key}_ref.jpg
```

加载成功时：
- 插入 `contents_list` 第一位（在档案照片之前）
- Prompt 最前加：「请严格参考第一张图片所呈现的视觉风格（色调、光影、质感、构图）进行图片创作」

当 `style_key != "ghibli"` 时，自动剥除 `image_prompt` 中硬编码的宫崎骏风格前缀，避免风格冲突。

**支持风格（`styles.json` 配置）：**

| key | 风格描述 |
|-----|---------|
| `ghibli` | 宫崎骏吉卜力动画风格，温暖自然色调 |
| `spider_verse` | 漫画格子 + 高对比度色块，平行宇宙风格 |
| 其他 | 从 styles.json 动态读取，支持热更新 |

## 十、输出与存储

**生图模型：** `gemini-3.1-flash-image-preview`

**输出规格：**
- 4:5 竖版（目标 512×640px）
- PIL 强制后处理裁剪：偏差 >2% 时裁剪到标准比例

**上传路径（R2）：**
```
micink-assets-test/images/{user_id}/{session_id}/{1000+i}.png
```

**公开 URL：**
```
https://pub-8a9e994d008c4d3e875ef722bded6ab5.r2.dev/images/{user_id}/{session_id}/1000.png
```

**写回 DB：**
```json
strategy_analysis.scene_images = [
  {
    "index": 1000,
    "scene_description": "I am reporting to Zhang San...",
    "image_url": "https://...",
    "image_base64": null
  }
]
sessions.image_status = "completed"
```

**StrategyAnalysis 不存在时的兜底：**
- 先暂存到 `sessions.analysis_stage_detail["scene_images_pending"]`
- 最多重试 30 次（每次间隔 10s，共等 5 分钟）
- 超时则记录 WARNING，图片不丢失但无法关联
