# 数据备份方案

> 创建时间：2026-06-25
> 适用环境：测试服务器（34.74.255.48）/ 数据库 `gemini_audio_db_test`
> 状态：已部署，已验证

---

## 一、备份范围

### 1.1 已纳入备份：PostgreSQL 数据库（全量）

数据库 `gemini_audio_db_test` 共 22 张表，全部备份：

| 数据类型 | 涉及的表 |
|---|---|
| 用户账号、订阅 | `users` |
| AI 对话记录 | `sessions`、`analysis_results`、`strategy_analysis` |
| 生图数据（图片 URL） | `strategy_analysis.scene_images`、`sessions.cover_image_url` |
| 档案 + 声纹嵌入 | `profiles` |
| 知识图谱记忆 | `kg_persons`、`kg_events`、`kg_event_persons`、`kg_goals`、`kg_skills` |
| Live Mode 数据 | `live_turns`、`live_segments`、`live_events`、`live_speaker_mappings`、`live_summary_tasks`、`live_panel_batches` |
| 技能库 | `skills`、`skill_executions`、`user_skill_preferences`、`custom_skills` |
| 其他 | `skill_notes`、`verification_codes` |

### 1.2 未纳入备份：R2 文件（无需额外备份）

Cloudflare R2 存储的音频文件（`.m4a`）和生成图片（`.png`）不在此备份范围内。
R2 本身提供 99.999999999%（11 个 9）的数据持久性，无需额外备份。

---

## 二、备份策略

| 项目 | 配置 |
|---|---|
| 备份方式 | `pg_dump` 全量导出 + `gzip` 压缩 |
| 执行时间 | 每天凌晨 3:00（UTC+0，北京时间 11:00） |
| 本地保留 | 7 天（自动清理） |
| R2 远端保留 | 按年月目录永久存储，可手动清理 |
| 本地存储路径 | `/opt/backup/db/` |
| R2 存储路径 | `s3://micink-assets-test/db-backups/YYYY/MM/` |
| 备份日志 | `/opt/backup/logs/backup.log` |

---

## 三、部署信息

### 3.1 备份脚本路径

```
/opt/backup/db_backup.sh
```

### 3.2 Cron 定时任务

```bash
# 查看当前 cron
sudo crontab -l

# 输出应包含：
0 3 * * * /opt/backup/db_backup.sh >> /opt/backup/logs/backup.log 2>&1
```

### 3.3 目录结构

```
/opt/backup/
├── db_backup.sh          ← 备份脚本
├── db/                   ← 本地备份文件（保留 7 天）
│   └── gemini_audio_db_test_YYYYMMDD_HHMMSS.sql.gz
└── logs/
    └── backup.log        ← 每次备份日志
```

## 五、恢复流程

### 5.1 从本地备份恢复（首选）

```bash
ssh gemini-server

# 查看可用备份
ls -lh /opt/backup/db/

# 恢复到数据库（会覆盖现有数据，谨慎执行）
gunzip -c /opt/backup/db/gemini_audio_db_test_YYYYMMDD_HHMMSS.sql.gz \
  | sudo -u postgres psql gemini_audio_db_test
```

### 5.2 从 R2 恢复（本地文件丢失时）

```bash
ssh gemini-server

# Step 1：从 R2 下载备份文件
AWS_ACCESS_KEY_ID=cb5fd8146e35b4f280115a67fc5ea69c \
AWS_SECRET_ACCESS_KEY=43d6f571b776b86720bfa96b263a517e5f8c8c09b14cbc96e095e7ee81353571 \
aws s3 cp s3://micink-assets-test/db-backups/2026/06/gemini_audio_db_test_YYYYMMDD_HHMMSS.sql.gz /tmp/ \
  --endpoint-url https://65bbba67bcef53a9e38ad8b152048cc1.r2.cloudflarestorage.com

# Step 2：恢复到数据库
gunzip -c /tmp/gemini_audio_db_test_YYYYMMDD_HHMMSS.sql.gz \
  | sudo -u postgres psql gemini_audio_db_test
```

## 六、手动触发备份

如需立即备份（不等定时任务），执行：

```bash
ssh gemini-server
sudo /opt/backup/db_backup.sh
```

## 七、历史问题说明

原有备份脚本 `/opt/backup_db.sh`（2026-06-04 创建）因 cron 使用 `/bin/sh` 不支持 `source` 命令，**每日均以失败告终，从未成功执行过**。已于 2026-06-25 从 crontab 移除，替换为本方案。
