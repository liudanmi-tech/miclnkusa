## 一、产品概览

**Chattoon / WorkSurvivalGuide** 是一款职场 AI 助理 App：
- 用户录制职场对话 → AI 转录 + 情绪/风险分析 → 匹配教练技能 → 生成策略建议卡片 + 场景图片
- 支持 AI 聊天对话（SSE 流式）、实时录音（Live Mode，对接 Meta 智能眼镜）
- 内置知识图谱（持久化人物/事件/目标记忆）
- 订阅付费（免费 / 周订阅 / 月订阅 / 年订阅）

| 分析 | TikTok Business SDK（埋点） |

| `NewTaskCreated` | RecordingViewModel | TaskListViewModel | 创建新 Session 后 |
| `ChatSessionClosed` | ChatAIAssistantView | TaskListViewModel | 正常退出对话 |
| `ChatSessionDeleted` | RecordingViewModel | TaskListViewModel | 无输入退出删除孤儿 |
| `TaskAnalysisCompleted` | NetworkManager | TaskDetailView | 任务分析完成 |

**⚠️ 关键约束：** `TaskListViewModel.addNewTask()` 对 `sessionType == "chat"` 的 Session **不得** 调用 `setProcessing()`，否则录音按钮会被锁定。

## 八、核心功能流程

### 8.1 录音分析流程（Review Mode）

```
1. 用户点击录音
   iOS: RecordingViewModel.startRecording()
   └─ AudioRecorderService 采集 PCM

2. 用户点击停止
   iOS: RecordingViewModel.stopRecording()
   └─ NetworkManager.uploadAudio(fileURL:)
   └─ POST /api/v1/audio/upload（multipart，600s 超时）

3. 服务端处理（main.py）
   ├─ 音频上传到 R2（sessions/{user_id}/{session_id}/original.m4a）
   ├─ Gemini 转录（gemini-2.5-flash）
   ├─ Gemini Call #1：对话分析 → dialogues, mood_score, speaker_mapping
   ├─ 技能匹配（gemini-2.5-flash，阈值 ≥90，最多 3/类，emotion_recognition 强制置顶）
   ├─ 并行：策略卡片生成（Groq llama，有 Gemini 兜底）
   └─ 并行：场景图片生成（scene_image_generator.py → R2）

4. iOS 轮询
   GET /api/v1/tasks/sessions/{id}
   当 status='completed' → 展示 TaskDetailView
```

### 8.2 AI 聊天流程（Chat Mode）

```
1. iOS: RecordingViewModel.createChatSession(skillId)
   POST /api/v1/assistant/init-chat-session
   → 返回 session_id

2. ContentView 监听 chatSessionId != nil
   → fullScreenCover 展示 ChatAIAssistantView

3. 用户发送消息
   ChatAIAssistantViewModel.send(message)
   POST /api/v1/assistant/chat（SSE 流）

   SSE 事件格式：
   {"type": "chunk", "text": "..."}
   {"type": "done"}
   {"type": "suggestions", "items": ["...", "..."]}
   {"type": "meme", "category": "feel_you", "url": "..."}
   {"type": "baseline_data", "field": "value"}

   特殊消息类型（服务端处理）：
   - "__INIT__"  → 自动开场白
   - "__SWITCH__" → 切换技能
   - "__VOICE__" → 语音输入

4. 退出（有对话内容）
   POST /api/v1/assistant/close-chat-session
   POST /api/v1/assistant/generate-image-from-chat（Fire-and-forget）
   → NotificationCenter 发 ChatSessionClosed
   → TaskListViewModel 刷新列表

5. 退出（无输入）
   DELETE /api/v1/sessions/{id}（删除孤儿 Session）
   → NotificationCenter 发 ChatSessionDeleted
```

### 8.3 Convert-to-Image 流程（Chat 退出时）

```
1. iOS POST /api/v1/assistant/generate-image-from-chat
   Req: {session_id, transcript[]}  → 立即返回

2. 服务端 Fire-and-forget（background task）：
   ├─ scene_image_generator.generate_scene_images()
   │   ├─ Gemini 提取 1-3 个场景描述
   │   ├─ 逐场景生成图片（Imagen）
   │   ├─ 上传到 R2（sessions/{uid}/{sid}/images/{n}.png）
   │   └─ 写入两处：
   │       ├─ strategy_analysis.scene_images（场景图列表）
   │       └─ sessions.cover_image_url（列表缩略图）
   └─ _async_session_finalize()
       ├─ 仅传用户消息（排除 AI 回复，防止稀释情绪信号）
       └─ Gemini 生成：card_title + mood_state + emotion_type
           写入 sessions 表

   图片数量限制：
   - Free 用户：1 张
   - Pro 用户：3 张
   - Live Mode：5 张

3. iOS 轮询 GET /api/v1/tasks/sessions/{id}
   cover_image_url != nil → 显示图片
```

### 8.4 Live Mode 流程（实时录音，对接 Meta 眼镜）

```
1. iOS POST /api/v1/live/sessions → 返回 session_id + WebSocket URL
   服务端检查孤儿 Session（WS 断开 >2min → 标记 abandoned）

2. WebSocket（live_audio.py）
   iOS 流式发 PCM 帧
   服务端：
   ├─ Deepgram 实时转录
   ├─ 逐轮次：说话人分离（speaker_label）
   ├─ 声纹匹配（ECAPA/CAM++ 192维）
   ├─ 技能匹配（Gemini 2.5 Flash）
   └─ 写入 live_turns 表

3. SSE 推送（live_sse.py）
   事件类型：
   - speaker_identified  → 说话人识别结果
   - turn_completed      → 新增一条对话
   - suggestion          → 实时建议
   - skill_match         → 匹配到技能
   - segment_split       → 分段切换
   - session_renewed     → Session 续期

4. 用户确认说话人
   POST /api/v1/live/sessions/{id}/confirm-speaker
   → LiveSpeakerMapping (confidence=1.0, method='user_confirmed')

5. 用户点击结束
   POST /api/v1/live/sessions/{id}/end
   服务端 Fire-and-forget（3 个并行 task）：
   ├─ Task 1 _task1_summary
   │   聚合 segment.running_context → Gemini → card_title + live_summary
   ├─ Task 2 _task2_images
   │   generate_scene_images（最多 5 张）→ R2
   └─ Task 3 _task3_skills
       去重 matched_skills → skill_cards → strategy_analysis

6. iOS 轮询 GET /api/v1/live/sessions/{id}/summary-status
   summary_status='completed' → 展示卡片
```

### 8.5 订阅配额系统

**配额规则：**

| 方案 | product_id | 聊天次数 | 生图次数 | 档案数 | 周期 |
|---|---|---|---|---|---|
| Free | — | 5次（终身） | 5次（终身） | 2 | 终身 |
| Weekly | com.miclnk.pro.weekly | 30次 | 7次 | 7 | 7天 |
| Monthly | com.miclnk.pro.monthly | 100次 | 30次 | 15 | 30天 |
| Yearly | com.miclnk.pro.yearly | 无限 | 365次 | 30 | 365天 |

**服务端计数（从 sessions 表实时计算）：**
```sql
-- 聊天次数
SELECT COUNT(*) FROM sessions WHERE user_id=? AND session_type='chat' AND created_at >= period_start

-- 生图次数
SELECT COUNT(*) FROM sessions WHERE user_id=? AND session_type='chat'
  AND cover_image_url IS NOT NULL AND created_at >= period_start
```

**滚动周期计算：**
```python
elapsed_days = (now - sub_period_start).days
current_period_start = sub_period_start + timedelta(days=(elapsed_days // period_days) * period_days)
```

**iOS 端（SubscriptionManager.swift）：**
```swift
// yearly 无限 → 服务端返回 nil → 客户端映射 -1
var chatLimit: Int? = nil  // nil 表示无限
var canStartChat: Bool { chatLimit == -1 || chatCount < chatLimit! }
```

**错误码：**
- `403 chat_limit_reached` → 付费墙
- `403 profile_free_limit_reached` → 付费墙
- `403 profile_pro_limit_reached` → Toast

## 十、声纹识别架构

### 10.1 模型选择

| 语言 | 模型 | 维度 | 数据库字段 |
|---|---|---|---|
| 中文 | CAM++ | 192维 | `voice_embedding_zh` |

### 10.2 匹配流程

## 十五、已知约束和注意事项

### 15.1 代码约束

| 约束 | 说明 |
|---|---|
| `iOS_Code_Files/` 只读 | 所有 iOS 改动必须在 `Models.swift/WorkSurvivalGuide/` |
| `NetworkManager.swift` 单一入口 | 每个新 API 必须在此添加方法 |
| 服务端无 git | 部署必须用 scp，不能 git pull |
| main.py 是单体 | 新功能优先放 `api/` 或 `services/`，不要继续往 main.py 加 |
| PostgreSQL 本机运行 | Schema 变更必须 SSH 进服务器执行 ALTER TABLE |
| PBXFileSystemSynchronizedRootGroup | 新 Swift 文件自动编译，不需要改 .pbxproj |

### 15.2 ORM 历史问题

`users` 表有 3 个字段曾不在 ORM 模型中（已修复）：
- `apple_original_transaction_id`
- `subscription_product_id`
- `sub_period_start`

缺少这些字段会导致 `/subscription/verify` 返回 500。

### 15.3 变量名陷阱

`main.py` 中 base URL 变量名为 `baseURLForRead`（不是 `baseURL`）。

### 15.4 Chat Session 录音按钮锁定

`TaskListViewModel.addNewTask()` 中，`sessionType == "chat"` 的 Session **禁止** 调用 `setProcessing()`，否则录音按钮被锁定无法解锁。

### 15.5 情绪分析仅用用户消息

`_async_session_finalize()` 分析对话情绪时，只传用户消息，排除 AI 回复，防止 AI 措辞干扰情绪判断。
