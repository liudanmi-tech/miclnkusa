# /change — 标准改动流程

**用法**：`/change [你要改的内容描述]`

## 执行流程（按顺序，不可跳过）

### Step 1 — 读取规范文档
读取 CLAUDE.md 和 ~/Desktop/0226new-doc/ 目录下的相关模块文档

### Step 2 — 分析涉及模块，读取对应文档
列出 ~/Desktop/0226new-doc/ 下的文件，根据改动内容读取相关模块文档

### Step 3 — 输出影响分析报告（等待用户确认，不得跳过）
格式：
【改动影响分析】
需求：[复述改动描述]
已读文档：[列出]
直接涉及文件：[列出]
可能受影响：[列出]
需验证功能：[列出]
风险评估：[低/中/高]
---
确认后我开始改代码？

### Step 4 — 创建 Git 分支
git checkout -b fix/[描述] 或 feat/[描述]

### Step 5 — 最小化改动
只改必须改的，不顺手重构

### Step 6 — 输出改动摘要，等待确认后再 commit

### Step 7 — Commit
git add [具体文件] && git commit -m "fix/feat: [描述]"

## 硬性规则
- 不在 main/master 直接改代码
- Step 3 和 Step 6 必须等用户确认
- 不一次改超过 5 个文件
- 不顺手重构无关代码
